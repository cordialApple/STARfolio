# Stage 6c — Streaming-STT swap (Stage A, planned)

Part of the [build plan](../build-plan.md) · Context to load: [full-duplex-migration](../architecture/full-duplex-migration.md) · [voice](../architecture/voice.md) · [process-and-ipc](../architecture/process-and-ipc.md) · [ai-layer](../architecture/ai-layer.md)

Goal: swap the ASR front end — replace [Stage 6b](stage-06b-streaming-voice.md)'s whisper-era faked streaming (sliding-window re-decode + LocalAgreement-2 + energy-RMS VAD with a fixed 1.28 s hangover) with **Kyutai STT** (`stt-1b-en_fr`), a native-streaming model that emits committed word tokens and a **semantic VAD** end-of-turn signal at ~500 ms — with no WER penalty. This is Stage A of the [full-duplex migration](../architecture/full-duplex-migration.md) (see it for the current-vs-Stage-A diagrams): a text-in/text-out swap behind `app/src/main/voice/`. Everything downstream — `RollingTranscript` → IPC → the tiered LLM brain (Opus roadmap / Sonnet rubric scoring / deterministic reducer / Haiku phrasing) — is **unchanged**. Nothing here is built yet.

Why its own stage: 6b's streaming exists only because whisper is a batch model — six modules of prosthesis around that one fact. Kyutai STT dissolves the fact, so the stage is mostly *deletion* plus one adapter, but it fronts a real risk (new GPU inference server, new endpointing behavior) that must be spiked before anything depends on it. Stage A is **one shared user surface**: both [Stage 6d](stage-06d-cascade-streaming-tts.md) (cascade) and [Stage 6e](stage-06e-native-full-duplex.md) (native full-duplex) fork from it. Grounding posture holds unchanged: audio is data, never instructions, and Kyutai STT runs locally on the GPU — still no cloud STT, all audio stays on-device.

- [ ] 6c.1 **Spike (gate — do first):** stand up Kyutai STT on the target GPU; prove a streaming adapter emits committed word tokens + the semantic end-of-turn signal behind the existing voice IPC seam (`voice:partial { text, stableUpTo }`, final on endpoint); prove endpointing parity-or-better vs the whisper energy-RMS/1.28 s-hangover endpointer on interview-style speech with long thinking pauses (no mid-answer cut-offs). Anything failing here reshapes the stage while it's cheap; WER escape hatch is `stt-2.6b-en` at 2.5 s delay.
- [ ] 6c.2 STT adapter/server: local Kyutai STT server (GPU) + a main-process adapter under `app/src/main/voice/` speaking the same partial/final event shape the voice IPC already speaks. `stableUpTo` is redefined from "the LocalAgreement-frozen prefix" to "all committed tokens" — the UI contract holds, so the renderer does not change.
- [ ] 6c.3 Wire behind the seam: renderer capture (`recorder.ts` / `pcm-processor.js`) feeds the adapter; `RollingTranscript` and the tiered LLM brain consume it unchanged; the half-duplex gate stays (Stage A is still half-duplex).
- [ ] 6c.4 Retire the six whisper-era streaming modules the swap obsoletes: SampleRingBuffer usage, FrameSource, EnergyVad, StreamWindow, the whisper batch stream-decoder, and LocalAgreement-2. Stage 6's push-to-talk batch path is not part of this swap.
- [ ] 6c.5 On-hardware sustained pass: real mic + packaged build, full-length session; confirm endpoint latency ~500 ms (vs 1.28 s), no mid-thought cut-offs, sustained real-time behavior; document the new budget, superseding [6b's streaming budget](stage-06b-streaming-voice.md#streaming-budget-6b5).

**Checkpoint 6c**: a hands-free mock interview on the Kyutai front end — committed partials stream live, semantic end-of-turn takes turns without cutting off thinking pauses, the tiered brain behaves exactly as before, and all audio stays on the local GPU. This surface is the shared base Stages 6d and 6e branch from.
